# 写作 Agent 架构收敛

这里的目标不是套用某个框架名称，而是让写作任务有清楚的输入、可替换的执行能力、显式的状态和可测试的结果。

## 分层约定

1. Web/API：读取请求、检查输入、加载和保存文档，负责 HTTP 响应。
2. 依赖装配：把模型/生成器、配置、超时包装、指标记录等能力明确交给工作流。
3. 工作流：选择执行路径，协调规划、写作、检查和失败回退，返回结果。
4. 具体能力与基础设施：模型 Provider、资料检索、文档编辑、导出和存储。

依赖方向应从入口指向工作流和能力。工作流不能反过来导入 Web 入口，也不能从整个应用对象中查找任意全局函数。

## 本轮实际完成

- 整篇生成的 `GenerateGraphRequest` 不再携带 `app_v2`；执行时必须显式提供 `GenerateGraphDeps`。
- 章节生成的 `GenerateSectionRequest` 只保留章节、指令、已有正文和配置；移除未使用的 session 与应用对象。
- 增加 `GenerateSectionDeps`，声明章节执行实际需要的生成器与路由配置。
- Web 装配集中到 `web/services/generation_dependencies.py`，配置在每次装配时复制，避免运行中跟随环境变量变化。
- 章节生成在收到最终结果或发生错误时关闭底层生成器，结束其资源生命周期。
- 保持现有路由、新旧生成引擎选择、失败回退和响应格式；不增加依赖。
- `test_agent_workflow_boundaries.py` 检查反向依赖、请求字段、显式注入和生成器关闭行为。

## 如何扩展

新增调用入口时，构造任务 Request 和对应 Deps，再调用工作流；不要传 Web 模块。
替换模型或生成引擎时，替换 Deps 中的 callable，不在工作流内增加环境探测或服务查找。
测试时提供内存输入和假的生成器，不必启动 Web 服务或调用真实模型。

## 尚未完成的边界

- 整篇生成仍使用旧 session 作为任务状态，并通过注入的异常工厂保持原有 HTTP 错误行为。
- Web 装配器仍从旧应用入口读取能力；这是一处明确的兼容边界，不代表旧入口已全部解耦。
- 修订、局部编辑等旧工作流仍存在应用对象依赖，需按同样方式逐个迁移。
- 本轮没有实现全局任务队列、统一取消/超时预算、持久化检查点或全局缓存容量控制。
- 不新增自动重试、自动工具权限或自动转发行为，避免改变现有用户确认和失败语义。

后续顺序：迁移修订/编辑依赖 → 独立任务状态和错误类型 → 统一执行预算与取消 → 存储及缓存生命周期。
