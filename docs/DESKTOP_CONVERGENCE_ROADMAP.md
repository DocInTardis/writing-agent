# 精简与代码优化路线

当前目标：缩小体积，优化现有实现。优先保持用户文档和核心写作功能，不以换技术栈或增加框架为目标。

## 已实施（2026-09-04）

- 删除 12 份过时归档方案及失效引用；历史可从 Git 恢复。
- 移除没有实际调用者的学术表达模板缓存和旧缓存条目数据类。
- 生成文本缓存默认正文上限 64 MiB、500 条、7 天；按最近使用淘汰，写入/初始化清理过期内容，更新不误占新条数。
- 缓存索引紧凑存储并原子替换，同进程实例共享状态。仅管理已登记正文，不是所有缓存的统一配额，不做跨进程同步。
- 手动保存、自动保存和恢复版本使用独立的嵌套文档快照；自动保存仅在确有变化时复制。
- API 额度不足默认不切换到 Ollama；保留显式开启的兼容选项，不修改用户现有配置。
- 用户界面中选定的模型优先于环境配置缓存，避免旧缓存遮蔽新选择。
- 本轮验证结果以实际测试输出和交付说明为准，不把规划当作完成记录。

## 后续取舍原则

- 一个功能选一个主实现；删除无消费者的旧路径，不无限叠加 fallback。
- 短暂网络错误可有限重试；鉴权、余额或参数错误明确报告，不隐式切换供应商。
- 保留原子保存、版本隔离和恢复等数据保护机制。
- 模型由用户提供 API 并自由选择，优先验收 DeepSeek；不强制 Ollama，也不自动下载模型。
- 密钥与普通配置分离，不进入日志、文档或导出。
- 编辑器按接近 Word 的目标评估：中文输入、光标/选择、撤销、样式、表格、图片、分页、DOCX 及打印。
- 先让编辑器方便地独立验收，再决定修复还是替换内核；不承诺完整 Word 排版兼容。
- 桌面只保留一个正式入口，尚未确定技术方案，不同时重写编辑器与全部后端。
- 用户文档/附件/必要版本不是缓存；开发目录体积也不等于软件安装体积。
- 不再增加分散计划文档，重构稳定后再根据实际实现生成最小使用和开发说明。

## 后续实施顺序

1. 按实际调用关系继续删除冗余模块，优先减少重复运行时和默认执行路径。
2. 统一模型配置与修订/编辑入口，修复任务取消、过期结果覆盖和状态混用。
3. 完成编辑器易启动验收入口，建立典型文档与编辑行为基线。
4. 依据编辑体验、完整安装体积、启动与内存测量选择桌面方案。
5. 统一其他缓存、日志和检查点的容量/保留规则，验收旧数据迁移与离线编辑。

## 工作区边界

用户已有的 Tauri 源文件未提交删除，不属于本轮修改，不自动恢复或混入提交。
不清理共享 C 盘开发缓存，不删除整个 .data，不创建重复虚拟环境或重建 Rust/浏览器测试环境。
